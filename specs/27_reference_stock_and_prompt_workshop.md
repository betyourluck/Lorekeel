**追補 — 枠のクロップ（2026-08-28 ユーザー要望）**: 埋まった枠の hover 操作に切り抜きを
足した。動機は spec 25 の形から必然的に出るもので、**設定画集は「1 枚に複数人の立ち絵」**
（誰の参照かを Kataribe は知らなくてよい、という設計）ゆえに、**今の場面に居ない人物まで
毎回参照へ送られる**。作り直さずに削れる経路が要る。ダイアログは spec 28 のエディタの
メディアと**共通**（`CropDialog` は保存先を知らず bytes を返すだけの部品へ一般化した）で、
結果は `put_reference_bytes` で同じ枠へ差し替える（出力は WebP 固定 — 枠は拡張子を選ばず
backend が先頭バイトで嗅ぎ分ける）。同梱由来の枠は「入れ直す」で戻せるので、
不可逆なのはプレイヤーが入れた絵だけ。

## 動機

spec 24/25 で挿絵は動くようになり、2026-08-22 の LAN 実機で**参照画像が実際に効く**ことも
確定した（同 seed で参照あり＝銀髪/緑目/赤マフラーを保持、なし＝金髪ロング/青目に化ける）。
効くことが確定した以上、次に足りないのは**入力側をプレイヤーが動かせないこと**である。

1. **参照画像が作者の同梱物に固定されていて育たない。** `images/settings_sheets/` は
   パッケージの中にあり、プレイヤーが差し替える経路が無い（spec 25 は「UI からの登録」を
   意図的にスコープ外にした）。だが参照は**遊んでいるうちに育つ** — 主人公の顔が固まってきた、
   この背景を基準にしたい、という更新はプレイ中に起きる。今は起きても書けない。
   **育つ契機はプレイの最中だが、束ねる単位はパッケージにする**（決定 2。プレイスルー単位に
   束ねると、ロードのたびに育てたものが巻き戻る）。
2. **スタイル指定が LLM に言い換えられる。** `user_prefix` は最終プロンプトに入らず、
   プロンプト書きへの素材（「# スタイル指定（プレイヤーから。必ず反映）」）として渡るだけで、
   LLM が自分の言葉に置き換える。ComfyUI にタグ列（`masterpiece, watercolor`）を渡したい
   ときこれは実害で、**原文が保たれないなら様式指定として機能していない**。
3. **seed が乱数なので A/B が成立しない**（`pid ^ scene_seq ^ nanos`）。参照を差し替えて
   比べるのが 1 の目的なのに、比べる手段が無い。1 を作っても「変わった気がする」しか返らない。

三つは同じ向きを持つ — **挿絵の入力（参照とプロンプトと seed）を、作者と LLM の手から
プレイヤーの手へ移す**。本 spec はその一手である。正本・語り・prompt caching には触れない
（spec 24 以来の提示層の境界は不変）。

## 何を作るか

### A. 参照ストック — セッションへの写し取り

**`images/settings_sheets/` は種であって参照先ではなくなる。** これが本 spec の核。

1. **置き場**: `app_data/refs/<パッケージパスの FNV 16 桁>/ref{1,2,3}.{png|jpg|jpeg|webp}`。
   FNV は `package_save_stem` と**同じ関数**で求める（入力はパッケージパスのみ。スロット番号は
   `save_file_name(stem, slot)` が別途付与する [lib.rs:1290]）。粒度は**パッケージ単位**。
   autosave とスロットは別粒度なので「セーブと同じ粒度」という表現は使わない。
2. **写し取りは初回だけ**（決定 3）。`refs/<FNV>/` が**存在しない**ときに限り、パッケージの
   `images/settings_sheets/` を `pick_settings_sheets` で選んで `ref1..k` へコピーする。
   以後 **package 側は原則読まない — 例外は A-4 の「入れ直す」のみ**。
3. **ゲーム中に効くのはセッションフォルダだけ。** 生成時の参照解決は `ref_stock::load_refs(dir, max)`
   の 1 経路で、**index 昇順**に読む（**ファイル名順ではない**）。当初は harness 側の読み取りを
   ディレクトリ引数へ一般化する案だったが、**実装時に棄却した** — あちらはファイル名順なので、
   ユーザーが手でフォルダに置いた `aaa.png` が `ref1.png` より前に並び、**枠番号とワイヤ番号が
   食い違う**（A-5 の不変条件を送信側だけが破る）。`ref{n}` の n で並べれば UI の枠列と送る列が
   同じ関数から導かれる。
4. **ダイアログの操作は 3 つ**:
   - **入れ替え**: 枠をクリックすると `sess.last_image` の原本 bytes をその枠へ書く
     （frontend は画像を持ち回らない＝IPC に bytes を流さない）。8MB 超は弾いてトースト（決定 8）。
   - **削除**: その枠を消し、**後ろを前へ詰める**（決定 10 の不変条件）。**0 枚まで消せる**＝
     参照なし生成に戻る（spec 25 の「refs=0 なら spec 24 と byte 一致」経路がそのまま受ける）。
   - **同梱の参照画像を入れ直す**: package の種を再び写す。**2 の初回限定を破る唯一の経路**で、
     空フォルダに対しても書き込む。削除の不可逆性はこのボタンが解消する。
5. **前詰め不変条件**（決定 10）:
   > `refs/<FNV>/` には `ref1..k`（k = 0..MAX_REFS）が**常に前詰めで**存在し、`ref{k+1}` 以降は
   > 存在しない。

   削除は物理ファイルを消して後続を前へリネームする（`ref2.jpg` → `ref1.jpg`、拡張子は保持）。
   これで **UI 番号 = ファイル名番号 = ワイヤ番号 `%ref_n%` が恒等的に一致**し、「2 番に入れたのに
   1 番として送られた」が構造的に起きない。ワイヤ側の詰めは冪等な安全弁として残すだけになる。
6. **表示は `asset://`**: `app_data/refs/` を `asset_protocol_scope().allow_directory` で許可し、
   command は**パスを返すだけ**にする（サムネイル data URL を毎回 IPC に流さない。同型の動的
   許可が [lib.rs:2434] と [lib.rs:2864] に既にある）。
7. **設定タブの一覧を実効値へ**: 現行 `list_settings_sheets` は package しか見ておらず、
   このままだと**実際に送られる 3 枚を示さなくなる**。セッションフォルダの現物を見せる。
   **出所（同梱由来／プレイヤー）は出さない**（決定 11）。
   **送られなかったものは理由つきで出す** — `Oversize`（8MB 超）/ `OverLimit`（枠の外）/
   **`Unrecognized`（`ref{n}.*` でない ＝ 手でフォルダに置かれたファイル）**。3 つ目は A-3 の
   index 順読みが生む新しい沈黙（フォルダを開けるのだから、置く人は必ず出る）で、黙って
   無視すると「入れたのに効かない」になる。

### B. プロンプト工房

1. **スタイルは直結する**（決定 5）。最終プロンプト＝`[スタイル文字列] + [LLM が書いた場面
   プロンプト]`。スタイルは LLM を通らないので**原文が保たれる**。
   ただし LLM から**見えなくはしない** — 見えないと「水彩」と指定した横で LLM が
   `photorealistic` と書き、1 本のプロンプトの中で矛盾する。素材節は残し、役割だけ変える:
   「この文字列はプロンプト先頭に原文のまま前置きされる。重複して書かず、矛盾する画風語も
   書かない」。**素材節の style は 300 字で切る**（矛盾回避に要るのは要旨だけ。直結される
   最終プロンプトには全文を使う。切った分は `TOTAL_BUDGET` に算入したまま＝入力は有界）。
2. **追加指示は LLM 経由**（決定 6）。「引きの構図で」「二人が向かい合うように」のような
   場面依存の意図は、語りと合成されないと壊れる。`ImagePromptRequest.direction`（予算 300 字、
   `TOTAL_BUDGET` に算入）として素材に載せる。
3. **最終プロンプトを見せ、手で直せる**。ダイアログ上段に**合成後の最終プロンプト**を出し、
   編集して「この文字列でそのまま生成」を押すと `prompt_override` として **verbatim で送る**
   （スタイルの再前置きもしない＝**見えているものが送られるもの**）。
4. **seed 固定トグル**（決定 7）。固定時は保存された seed を使う。**置き場は設定タブ**
   （ダイアログでなく設定＝永続する値なので。`toBackendConfig` は comfy 以外へ `lock_seed` を
   送らない＝spec 26 の「他プロバイダへ漏らさない」写像規則と同じ形）。
5. **合成は純関数**:

   ```
   compose_prompt(style, scene, override) =
       override（非空なら）                      // 手書きが最終形（決定 9）
       それ以外は [style.trim(), scene.trim()] の非空を区切り文字で連結
   ```

   `GeneratedImageView.prompt` は**最終送信文字列**を返す（override なら override、そうでなければ
   合成結果）。現在は LLM が書いた文だけを返しており、UI が「送られた文」を示していない。
6. **最終プロンプト長のチェックは置かない。** ComfyUI に明確な上限は無い（CLIP の 77 トークン窓
   は超過分が chunk 分割される）ので、閾値を置くと根拠のない誤警告になる。OpenAI / Gemini は
   API 側の上限に当たればエラー本文がそのまま surface される既存経路に乗る。

### C. `CodeEditor.vue`（CodeMirror 6）

汎用コンポーネントとして作る（`language` prop、Compartment で言語・テーマ・読み取り専用を
差し替え）。今回使う言語は **plaintext（プロンプト）+ json（ワークフロー欄）**。
`@codemirror/lang-yaml` は**パッケージ YAML エディタに着手する時に足す**（依存は後から積める）。
テーマは Kataribe の ink/parchment/ember に合わせて自前で書く（Fuseforks の配色は持ってこない）。

## 決定事項

1. **`images/settings_sheets/` は種。** ゲーム開始後は原則読まない（例外は「入れ直す」）。実効値は
   セッションフォルダの 1 箇所だけ（合成規則を持たない＝「どっちが出るか分からない」が構造的に
   起きない）。`initial_state` が package 宣言を `GameState` へ seed して以降 state が正本、と同型。
2. **紐づきはパッケージ単位**（`app_data/refs/<FNV>/`）。プレイスルー単位（セーブ連動）は
   **採らない** — スロット 1 をロードすると育てた参照が巻き戻り、育てる機能の意味が消える。
3. **写し取りはフォルダ不在時のみ**（ユーザー決定 2026-08-23）。新規ゲームのたびに写すと
   消した絵が毎回復活し、削除機能が実質無効になる。続きから／スロットロードでも写さない。
4. **セーブには何も入れない。** 状態はファイルの存在と前詰め順序そのもの。`SessionSave` は無改修。
   **第二の真実源（メタファイル）を持たない。**
5. **スタイルは直結・ただし LLM からは見える**（矛盾防止。素材節は 300 字で要旨だけ）。
6. **追加指示は揮発**（決定 12 の三層）。恒久にしたい様式指定はスタイル欄が受ける。
   **消し忘れた一言が以後の全生成に効き続ける**のを構造的に防ぐ。
7. **`lockSeed` / `seed` は localStorage の共有部**（`ImageGenSettings` の top-level。spec 26 の
   共有部/スロットの線引きに従う）。ただし **UI は comfy のときだけ有効**にし、openai / gemini
   では無効表示にする（API に seed が無いので、押せるのに効かない状態を作らない。ネガティブ
   プロンプト欄の既存の扱いと同じ流儀）。
8. **上限は二層 + 合計**:
   - 種の写し取り = `SHEET_MAX_BYTES` 4MB 維持（**配布物由来なので配布作法が適用される**）
   - プレイヤー挿入 = 8MB（**セッションフォルダは配布されないので配布作法は適用されない**。
     実測の生成画像は 1〜3MB で、当たるのは `highest` の上端だけ）
   - 送信合計 = 12MB raw。超えたら後ろ（ref3 → ref2 の順）から落としてトースト。
     **Gemini の inline は base64 で 4/3 に膨らむので、上限を上げただけだと静かな 400 に化ける。**
9. **`prompt_override` はスタイルを再前置きしない。** 手書きが最終形。
10. **前詰め不変条件**（A-5）。**写し取り判定はフォルダの存在のみで、ファイル数を見ない** —
    全削除で空フォルダになっても初期化済み扱い。`.initialized` のようなマーカーは第二の真実源に
    なるので持たない。
11. **出所（同梱由来／プレイヤー）は保存も表示もしない。** 動機は「消したら戻せるか」だが、
    **「入れ直す」が常にあるので同梱由来は常に復元可能**であり、失われるのはプレイヤーが入れた
    絵だけ、という規則で運用は閉じる。bytes 比較による導出も検討したが、spec 17 で作者がシートを
    差し替えると**写し取り済みの絵が「プレイヤー由来」に化ける**ので、正しくない表示になる。
12. **ライフサイクルは三層**:

    | 層 | 対象 | 消える契機 |
    |---|---|---|
    | 永続 | `refs/` のファイル・`userPrefix`（スタイル）・`lockSeed` / `seed` | 明示的な削除のみ |
    | セッション揮発 | `direction`（追加指示）・`sess.last_image`（spec 24 で定義済み） | 新規 / ロード / 遷移 |
    | 1 回きり | `prompt_override` | 送信したら捨てる |

## 波及と、意図した副作用

- **同梱由来は常に「入れ直す」で復元できる。失われるのはプレイヤーが入れた絵だけ。**
  UI 文言でこの規則を伝える（出所表示を持たない代わりの説明責任）。
- **spec 17 の更新は参照画像に反映されない。** 作者がシートを差し替えても写し取り済みの
  セッションには入らない（育てたものを上書きしない＝意図どおり）。取り込みたい人は
  「入れ直す」を押す。台帳に書かないと「更新したのに変わらない」を後で踏む。
- **マルチプレイ（spec 23）は無風。** 画像生成はホストの backend だけが回す。中継で配られた
  パッケージは `app_data/packages/table/{sha256}` にあり、パスが違うので FNV も違う＝卓ごとに
  別のセッションフォルダになる。
- **参照の循環**: 参照ありで生成した画像を参照へ入れると、実測済みの副作用（**参照の無地背景が
  構図に漏れて枠つきビネットになる**）が複利で増幅しうる。v1 では警告しないが記録する。
- **パッケージ YAML エディタは spec 17 の `tree_hash` と正面衝突する。** 方針は決定済み
  （**編集したらフォーク＝別パッケージ扱い**。出所メタを外せば更新機構の対象外になる既存経路に
  乗る）。設計は別 spec、本 spec では `CodeEditor.vue` の器だけ用意する。

## スコープ外（v1）

- パッケージ YAML エディタ本体（別 spec）/ リサイズ・再エンコード（`image` crate を足さない）/
  出所の導出表示（決定 11）/ entity ごとの参照（spec 25 で撤回済み）/ 参照ストックの卓共有 /
  枠の並べ替え（削除＋入れ直しで足りる）/ OpenAI・Gemini の seed（API に無い）。

## PoC

- **写し取り**: フォルダ不在なら種を `ref1..k` へ前詰めで写す・**存在すれば写さない**（削除した
  絵が復活しない）・4MB 超と未対応拡張子は種の段階で落ちる・**種が 0 枚でもフォルダは作る**
  （二度目に写さないため）・「入れ直す」は空フォルダにも書く。
- **前詰め不変条件**: `ref2` を削除すると `ref3` が `ref2` へリネームされる（拡張子保持）・
  中抜けが残らない・`ref1..3` 以外のファイル名が生まれない。
- **入れ替えと削除**: 枠へ書く／消す／0 枚まで消せる・**0 枚のとき生成リクエストが spec 24 と
  byte 一致**（spec 25 の不変条件が写し取り後も保たれる）・8MB 超は弾いて理由を返す。
- **送信合計**: 合計 12MB 超で後ろから落ち、落とした事実が呼び出し側へ返る。
- **`compose_prompt`（純関数）**: style 空なら場面のみ（区切り文字が混入しない）・場面空なら
  style のみ・両方あれば区切って連結・`override` 非空なら **verbatim**（style を前置きしない）。
- **プロンプト書きの素材**: `direction` が user 節に載る・空なら節が出ない・style 節が
  「前置き済み・重複禁止」の文言になっている・**style が 300 字で切れる**・予算超過時の削り順
  （語り → world）が変わらない。
- **seed**: 固定 ON で同じ seed が 2 回の生成に渡る・OFF で従来の乱数式。
- **送る列の順序**: `ref{n}` の n 昇順で読む（ファイル名順ではない）・**手で置いたファイルは
  `Unrecognized` として理由つきで返る**・枠外は `OverLimit`・8MB 超は `Oversize`。
- **frontend**: `asset://` でのパス解決・設定タブの一覧がセッション側の現物を出す・
  seed トグルが comfy 以外で無効表示。

## UI の決定（2026-08-23 ユーザー決定、rev2 の未決 3 点）

13. **ダイアログは 2 枚**（参照ストック / プロンプト工房）。1 枚に混ぜると縦が伸びて会話ペインを
    覆う。A/B のときは両方開く。
14. **「そのまま生成」にも `scene_seq` の世代チェックを掛ける。** 挿絵は現在の場面の絵として
    表示・保存されるので、別の場面に貼られるほうが混乱する。
15. **枠の数は `MAX_REFS` から生成する**（3 固定で組まない）。プロバイダ別に割れたとき UI が
    追従する。`SettingsSheetsView.max` が枠数を運ぶ（Phase A で実装済み）。

## 実装時に見つけた穴（Phase A、2026-08-23）

**査読の 11 点はどれも「仕様どうしの衝突」だったが、実装で出たのは「仕様が生む新しい沈黙」だった。**
A-3 を当初案（harness の読み取りをディレクトリ引数へ一般化＝**ファイル名順**）で書くと、A-5 の
前詰め不変条件を**送信側だけが破る** — 設定タブに「フォルダを開く」がある以上、ユーザーは
そこへ手でファイルを置く。`aaa.png` は `ref1.png` より前に並ぶので `%ref_1%` を奪い、削除は
`ref1.*` を消すので**画面と送信内容が恒久的にずれる**。

直し方は二つ考えられた —（i）送信も stock も同じ順序規則にする（ii）手置きも正規の入れ方にする。
**(i) を採った**（枠は 3 つで有限なので、置いた 4 枚目をどう扱うかという別の問いを増やさない）。
その帰結として手置きファイルは送られなくなるため、**`Unrecognized` を理由として足した**
（A-7）。沈黙を作らずに済ませる代償が理由コード 1 個なら安い。

harness 側の一般化（`load_sheets_from` / `pick_sheets`）は**この判断で不要になったので差し戻した**
（使われない汎用関数を残さない）。種の読み取りは `load_settings_sheets` のまま = **配布作法 4MB は
種にだけ掛かる**という決定 8 の線引きが、コードの形としてもそのまま残った。


## Phase B の実装メモ（2026-08-23）

- **手書き（`prompt_override`）ならプロンプト書きを呼ばない。** 手書きが最終形なので LLM を
  通す意味が無く、通せば待ち時間と課金だけ増える。`compose_image_prompt` は override を
  受けたら他を混ぜずに返すので、この分岐は backend の 1 段の `if` に収まった。
- **スタイルの二重化を「予算に算入したまま切る」で解いた。** 前置きされる側は全文・素材節は
  300 字。査読は「予算から除外」を提案したが、除外すると入力が無制限に伸びる（予算の目的は
  入力の有界性）。切って算入すれば、長いスタイルを書いた人はその分だけ語りの枠が減る＝
  トレードオフが本人に返る。
- **`lock_seed` は comfy 以外へ送らない。** UI の無効表示だけだと、設定を触った後にプロバイダを
  変えた人の値が wire に残る。spec 26 で `negative` / `workflowJson` に入れた写像規則と同型。


## Phase C+D の実装メモ（2026-08-23）

- **CodeMirror は動的 import だけにした。** 素朴に静的 import すると main bundle が 326KB →
  733KB（gz 105→238KB）になり、**設定を一度も開かないセッションでも起動時に解析される**。
  TTS の `@aituber-onair/voice` で同じ判断をした前例があるので、そこに揃えた（結果: main は
  333KB、`CodeEditor` は 406KB の別 chunk で必要時のみ）。
- **ワークフロー JSON 欄を先に CodeEditor へ移した。** 数百行を貼る欄で、構文エラーが黙って
  通り、`%ref_1%` を目で探す欄でもある — `lang-json` + `lint` が効く唯一の場所という当初の
  読みどおりだった。プロンプト欄は `language: "text"`（行番号も lint も付けない。文法の無い
  文章に赤線を引くのは誤警告にしかならない）。
- **枠の UI は「末尾の空きだけ押せる」**。前詰め不変条件は backend が保証するが、UI が中抜けの
  空き枠に入れられると `put_slot` の丸めに頼ることになる。押せる場所を絞れば丸めは保険で済む。
- **参照ストックのダイアログは画像が無くても開ける。** 削除と入れ直しは挿絵の有無と無関係に
  要る操作で、「まず 1 枚生成しないと参照を消せない」は倒錯している。


## 追補（2026-08-24、ユーザー要望 2 件）

### ローカルファイルからの取り込み + WebP 変換

参照の入れ方に**ローカルファイル**（クリックで選ぶ / カードへドロップ）を足した。
**変換は WebView（Chromium）で行う** — `image` crate は足さない（スコープ外の線を保つ）。Chromium は
`canvas.toBlob("image/webp", q)` で lossy WebP を**ネイティブに**書けるので、Rust 側に libwebp
（C ビルド・3 OS の CI）を持ち込まずに済む。長辺 1536 に縮め（Shape の最大辺 = それ以上は参照として
使われない）、品質 0.88（写真 1536px で概ね 150〜400KB）。

- 送りは **raw body**（`invoke(cmd, Uint8Array, { headers })` → `tauri::ipc::Request`）。JSON の
  `number[]` は 8MB で数千万要素になる。枠番号とプロバイダはヘッダ。
- **mime は backend が先頭バイトで嗅ぎ分ける**（`sniff_mime`）。frontend の申告を信じない — 変換が
  失敗して元の bytes がそのまま来ても、実体に合った拡張子で入る（拡張子と中身のずれは後で全経路を
  騙す）。`toBlob` が WebP を返せない環境は PNG へフォールバック（同じ理由で正しく入る）。
- 決定 4/11 の「frontend は画像を持ち回らない」は**サムネイルの話**で、ユーザーが選んだファイルの
  一回きりの上りは別物（上限 8MB で有界）。

### 浮遊パネルへ（モーダルの箱を捨てる）

「業務ツールっぽくしない」の要望。`FloatingPanel.vue` = 会話ペインの右下に**浮かぶ半透明のガラス**
（`bg-ink/65 backdrop-blur`・熾火の上辺・下から浮き上がる入場）。**幕を張らない**のが設計の核 —
挿絵や参照を触る作業は「いま出ている絵を見ながら」やるもので、画面を暗幕で覆うと比べる相手が消える。
閉じるのは ✕ と Esc だけ（場面のクリックは奪わない）。参照の枠は**机に置いた写真**（わずかな傾き・
hover で正す・操作は hover で浮き出る = 常設すると写真でなく業務の表になる）。

**✅目視 Green（2026-08-24 ユーザー実測）**: 見た目 OK・サムネイル表示 OK（= `?v=` は asset
protocol を素通り、#86 の未確認が解消）・圧縮実測 **1.3MB → 36KB**。追補 FB「入れ直すに警告」→
`askConfirm`（不可逆で押した瞬間の異変が小さい操作には確認 = シードリセットと同じ線。削除は
1 枚ずつ・即座に見えるので付けない）。**spec 27 は追補込みで Done。残る未実測 = seed 固定での
参照 A/B のみ**（機構は入った・比較プレイは未）。

## seed 固定と A/B（2026-08-26 実機で確定）

**seed を固定しても絵は一致しない。止まっていない変数がもう一つある — プロンプトである。**

ユーザーが「seed 値固定でも同じ絵にならない、内部でランダムにしているのか」と報告した。
候補は 3 つあった: ①プロンプト書きの LLM 出力が毎回違う ②ワークフローに `%seed%` が無く
ComfyUI 側の乱数になる（#83 と同型の沈黙）③プロバイダが comfy でない（seed は wire に載らない）。

**切り分けはユーザーが ComfyUI を直に叩いて済ませた** — 同じ seed（12345）と同じプロンプトで
Kataribe と**同一の出力**が再現した。これで ②③ は落ち、`%seed%` が正しく届いていること・
ComfyUI が決定論であることが同時に取れた。残る変数はプロンプトだけ。

原因は設計どおりの挙動である。`lock_seed` が固定するのは**サンプリングの運**だけで、
`prompt_override` が空なら生成のたびにプロンプト書きの LLM 呼び出しが走り（`lib.rs`）、
その出力が毎回違う文字列になる。**A/B には二変数を止める必要がある**:

1. ふつうに 1 枚生成する（LLM がプロンプトを書く）
2. プロンプト工房を開く — 上段には**その時送った最終送信文字列**が既に入っている
   （`PromptDialog.vue` が `generatedImage.prompt` で初期化する）
3. 「そのまま生成」を押す（= `prompt_override`、LLM を呼ばない）
4. 以降、**参照だけ**を差し替えて比べる

つまり seed 固定と `prompt_override` は**対で初めて A/B が立つ**。同じ Phase B に入れたのは
そのためだったが、依存関係をどこにも書いていなかったので実際に踏んだ。設定タブの
`lockSeedHint` と本節に明文化する。

### 分割と灰色は Krea 2 の性質（n=2）

同日、分割・コマ割りは ComfyUI 側のプロンプトと negative で防げること、しかし**参照の無地背景が
灰色の帯として画面に残るのは消えない**ことをユーザーが実測した。2026-08-22 の LAN 実機（n=1・
「プロンプト指示で大きく減るが消えない」）の n=2 で、当時の予測がそのまま持った。

理由は機構にある — Krea 2 の参照は `reference_latents` で Kontext 同型にトークン連結されるので、
モデルにとって参照は画風の見本ではなく**画面に入れるべき素材**であり、その背景も素材に含まれる。
negative で押し返す以外にレバーが無く、完全には消えない。**ここから出てくる Kataribe 側の
コード変更は無い**（作者の調整の領分）。

ただし押し返す唯一のレバーである negative の**既定値が空だった**ので、comfy スロットに既定値を
焼いた（`imageGen.ts` の `COMFY_DEFAULT_NEGATIVE`）。適用は新規スロットだけで、既存の空欄は
意図的な空かもしれないので上書きしない。

### 同梱テンプレートの撤去（ユーザー決定）

参照つきテンプレート `comfy_krea2_ref.json` を撤去し、同梱は**汎用 1 本**（`comfy_generic.json`）に
した。理由: ComfyUI を用意できる人は自分で絵柄を作るし使うモデルも違う（SD 系・Z1 など）、
かつ同梱すると**モデルの入手までサポート対象に見える**。

撤去でテンプレートが担っていた「置換語の入れ方の実例」が消えるので、**警告を 3 本に揃えた**
（`%ref_1%` / `%seed%` / `%negative%`）。どれも**落ちる値が実際に在るときだけ**鳴らす —
画集 0 枚・seed 非固定・negative 空欄なら差し込み先が無くても何も失われず、鳴らせば誤警告になる。
この日の切り分けで `%seed%` と `%negative%` の不在が二度候補に挙がり、どちらも警告が無かった。
フィクスチャとしては `app/src-tauri/src/testdata/comfy_ref_workflow.json` に残り、剪定の
live テストが使う。

### 追補 (2026-08-26 ユーザー要望)

**顔アイコンを参照ストックへドラッグできる。** spec 25 が意図的に捨てた「キャラごとの参照」を、
**機械に推測させず人が手で置く**形で取り戻した — 右ペインの presence 行の顔アイコンを枠へ
落とすと、そのキャラの絵が参照になる。engine も挿絵の機構も「誰の絵か」を知らないままで、
spec 25 の決定（entity 照合はしない）は不変。ユーザーの言: 「以前に自動で無理にやろうと
していたことを、手動でユーザーにやらせる」。

運ぶのは**アセット ID だけ**（`dataTransfer` の `application/x-kataribe-asset`）。backend の
`put_reference_from_asset` が `resolve_asset` でパッケージ内を解決して読み、既存の `put_slot`
へ流す — bytes は IPC に乗らない（`set_reference_slot` と同じ流儀）。ID の検証は
`resolve_asset` の既存規則（`^[A-Za-z0-9._-]{1,64}$` + `..` 除外）がそのまま担うので、
トラバーサルの面は増えていない。**mime は先頭バイトで嗅ぐので `.svg` のアイコンは弾かれる**
（画像モデルは SVG を受け取れない。静かに送って失敗させるより名指しで断る）。
store は `presentCharacters` に `iconId`（生の ID）を残す — `icon` は表示用に `asset://` URL へ
潰れるのでドラッグの荷物にできない。

**ドラッグ元は 2 つになった（2026-08-28 ユーザー要望）。** マップタブの詳細に出る場所の絵も
同じ経路で枠へ落とせる。`MapNode.image` は顔アイコンと同じ**不透明なアセット ID**（spec 01
Phase 0 の `images/` 配下）なので、`MapPanel` に `dragstart` を 1 本足して同じ
`application/x-kataribe-asset` を積むだけで済み、**backend は無改修**（`put_reference_from_asset`
は「同梱アセット」を受ける口であって顔アイコン専用ではない）。動機は「参照＝キャラの見た目」に
限らないこと — 場所の絵を参照に入れれば背景や画風の指定になる。渡すのは `selected.image`（生の
ID）で、表示用の `selectedImg`（`asset://` URL）ではない。未踏（frontier）の場所は backend が
`title`/`description`/`image` を伏せる＝詳細に絵が出ないので、**霧の向こうの絵は掴めない**
（ネタバレ衛生が呼び出し側の判断なしに保たれる）。

**実装で最初に詰まった箇所は自分のコードではなかった** → `failures.md #88`
（`dragDropEnabled` 既定 true が HTML5 ドラッグを横取り。2026-08-24 のファイルドロップも
一度も動いていなかった）。

**ダイアログのボタンはトグルになった**（押し直しで閉じる・開いている側は熾火で灯る・
`aria-expanded`）。参照ストックとプロンプト工房は**排他** — 浮遊パネルは 2 枚とも会話ペインの
同じ位置に出るので、両方 ON にできると 1 枚しか見えないのにボタンは 2 つとも「開いている」と
映り、状態表示が嘘になる。

## 追補（2026-09-03）— スタイルの写しを合成が落とす

ユーザー報告「スタイル指定が『画像に送るプロンプト』に二重で表示される」。設定に保存された
`userPrefix` は 1 回分で、二重になるのは合成の側だった。プロンプト書きには B-1 で
「前置きされるので重複して書くな」と渡しているが、これは素材節の規律で機械の守りが無く、
タグ列のスタイルを画風タグとして出力の先頭へ写すことがある（確率的なので「使っているうちに」
現れる）。合成が `スタイル, スタイル, 本文` を作っていた。

**決定（ユーザー選択 = 機械の守り）**: `compose_image_prompt` が、プロンプト書きの出力の先頭が
スタイル原文と一致するなら、その写しと直後の区切りを落としてから連結する。**写しは verbatim では
ない**（実データ: 誤字 `hyper-rea` を `hyper-real` に直して写す）ので、一致はタグ単位（`,` `、` `.` `。`
`;` 改行で区切る）で正規化（小文字・空白畳み）のうえ、5 文字以上のタグは編集距離 `1 + 長さ/10` を
許す。短いタグは完全一致のみ、語の途中では切らない。`prompt_override` は
verbatim のまま。規律（見せる側）と合成（通さない側）の二層 — 挿絵のプロンプト書きは LLM の
癖に依存する層なので、正しさを規律だけに置かない。
