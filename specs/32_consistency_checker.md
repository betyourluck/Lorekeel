# spec 32 — 一貫性検査 (Jev による語りの事後検査)

Status: **Phase A 実装中** (2026-09-21 起草。llm_client 側 = 実装済み・live Green)

---

## 動機 — この製品に唯一残っている構造的な穴

failures.md #23 (2026-06-24) が名指ししたとおり、**「正本 > 文章力」は ops にしか効かない**。
`adjudicate` は ops を全件裁くが、`narration` は engine が検証しない。op には engine の
バックストップが在るが **narration には原理的に無く、prompt 層が唯一の防衛線**だった。

以後 15 ヶ月、この穴から出た失敗クラスが少なくとも 8 件ある — #23 行商ネックレス /
#27 情景の二度出し / #28 マークアップ漏れ / #33 秘匿役職の描写開示 / #41 判定結末の認知漏れ /
#42 語りだけの移動 / #47 居ないキャラの発話 / #49 同行の既成事実化。
処方はすべて「規律を書く」と「事実を還流する」の二層で、**事後に検査する層だけが存在しない**。

2026-09-21 にユーザーが TypeSafe Jev を持ち込み、ここに入ることが実測で確認できた。

## Jev とは何か (2026-09-21 調査)

TypeSafe AI の「System One Model」。**文章を書かない** — 状態と質問を受け取り、確率つきの
型付き判断だけを単一の並列パスで返す。質問型は Choice (最大 255 択) / Score (2〜10 段階) /
Noul (真偽の度合い 0〜1) の 3 つだけで、**任意のスキーマを定義できるわけではない**
(公式ブログは「型安全な構造化出力」と広く書くが、docs を読むと質問の型を選ぶ形)。

- state + 最長質問で約 32k トークン、合計予算 約 64k
- $0.042/MTok 入力・出力無料。70〜500ms
- **質問は並列・独立**に評価され、レイテンシは質問数にほぼ依存しない
- できないこと (公式明記): テキスト/コード/要約/推論説明の生成、数値・日付・算術、
  画像音声動画、**敵対的入力への頑健性が弱い**

「幻覚できない」の射程は **出力の形を縛るが判断は縛らない** (Anthony Maio)。TypeSafe 自身も
この保証は「経験的でなくスキーマ構造による」と認めている。ベンチマークの参照ラベルは
ground truth でなく frontier モデル 2 つの一致で、CounterProof Research の監査 (2026-09-16) は
公開 20 ケース中 **19 件のうち 8 件で参照どうしが食い違う**と報告している。
**独立測定は Every の 1 件のみ**で、それも速度と価格であって判断品質ではない。

→ ゆえに **Jev に「良い語りか」を聞かない**。聞くのは state との照合だけ。美的判断には
ground truth が無く、それは TypeSafe 自身がベンチマークで踏んだ穴の再演になる。

## 実測 (2026-09-21、friday_lemmon の実プレイログ 11 ターン + 注入)

### 6 軸のギャップ

| 軸 | 正常 | 違反 | ギャップ | 照合の相手 | 検査の型 |
|---|---|---|---|---|---|
| 語りだけの移動 (#42) | 0.04〜0.05 | 0.90〜0.94 | **0.85** | location + op | 読解のみ |
| 未所持物の譲渡 (#23) | 0.07〜0.22 | 0.95〜0.96 | 0.73 | inventory | 読解+照合 |
| 不在者の発話 (#47/#49) | 0.08〜0.29 | 0.93〜0.95 | 0.64 | present | 読解+照合 |
| **過去の語りとの矛盾** | 0.03〜0.15 | 0.77〜0.96 | 0.62 | 過去の語り | 読解+照合 |
| **別人の特徴の混入** | 0.15〜0.21 | 0.77〜0.93 | 0.56 | profile | 読解+照合 |
| 秘匿の漏洩 (#33) | 0.12〜0.24 | 0.65〜0.83 | 0.41 | 秘匿属性 | 読解+**判断** |

**ギャップが検査の型と一致した**: 読解のみ > 読解+照合 > 読解+判断。切り分け実験でも
読解 0.96 / 照合 0.05〜0.09 / 複合 0.95 と出ている。秘匿だけ弱いのは**漏洩が明示でなく
示唆でも起きる**ため = 二値で切ること自体が無理で、これは原理的。

**実 GM の語り 11 ターン × 3 軸 = 33 判定で偽陽性ゼロ。** 225 字の実語りに 1 行だけ違反を
注入すると 0.08 → 0.93 / 0.10 → 0.95。

### 実データが教えた設計 (机上では出なかった)

1. **検査はターン開始時 (出発地) の presence で行う。** 移動ターン T7 を移動後の presence で
   判定すると 0.94 の誤検出、出発地なら 0.13。移動の語りは出発地で始まるため。
2. **移動検査は一方向でなければならない。** 実ログで起きていたのは #42 の**逆向き**だった —
   op は移動済みなのに語りが「ドアに手をかけた」で止まっている (T3=0.56 / T7=0.48)。
   次ターンは到着地前提で始まるので矛盾は生じず、**これは語りの作法で違反ではない**。
   ゆえに検査すべきは「op なし × 語りが移動」の一方向だけ。
3. **質問文は一文で 0.36 動く。** live テストで「話題に出るだけ・名前が出るだけで台詞を
   話していない人物は数えない」を落としたら 0.87 → 0.51。**質問文は GM_SYSTEM と同じ
   接地の文言**であり、テストで固定し、変更したら再測定する。
4. **「矛盾」でなく「混入」を聞く。** profile は否定を書かないので「A の特徴を B がやる」は
   厳密には矛盾しない (筆村が砂糖を二つ入れてはいけないとは書かれていない)。
   聞き方を変えるだけで 0.59 → 0.77。
5. **論点が 1 つになる形に割る。** 「分解せよ」ではない — 人物ごとに割ると
   「登場判定 + 矛盾判定」の 2 段になり、一括質問 (0.95) より弱くなった (0.41〜0.80)。

### 独立した第三者観察 (n=2 で一致)

経費申請 20 件の実測報告 (2026-09-21、X): 「まとめて聞くと正解率 6 割、質問を分けたら 95%」
「1 件 0.56 秒、20 件で 1 円未満」。**私の実測 (複合 0.28 → 単一論点 0.95) と独立に一致**。

### 観測した偽陽性の芽

T10 実語りの profile 矛盾が 0.29 と他より高い。T10 は「僕もあかりの彼氏だしね」という
**プレイヤーの捏造を GM が正しく訂正している**場面で、引用された「彼氏」が profile (幼馴染)
との食い違いとして拾われたと見られる。閾値以下だが、**プレイヤーの誤りを GM が引用して
訂正する場面は構造的に偽陽性を生む**。

## 設計

### 層の分け方

| 層 | 置くもの | 理由 |
|---|---|---|
| `llm_client/src/jev.rs` | `JevClient`・wire 型・encode/decode 純関数 | `LlmError` の一過性判定と backoff を共有。spec 30 の計器に載る。**`cargo test -p llm_client` でテストできる** (app backend は Tauri builder を通らず #89 型の穴が残る) |
| `harness/src/consistency.rs` | `ConsistencyChecker` trait + `impl for JevClient` + 質問の組み立て・解釈 (純関数) | 質問文は prompt と同じ接地の文言。`prompt.rs` の隣。fake を差せる |
| `app` | 設定・受理後の呼び出し・`TurnView` 搭載・dev 表示・jsonl 記録 | 画像生成と同じ流儀 |

**canonical `ChatRequest` には乗せない。** messages が無く tool-use でもないので、`Provider` の
match (chat のための seam) に足すと canonical が汚れる。

前例は `impl Summarizer for llm_client::LlmClient` (spec 10) — trait も実装も harness が持ち、
llm_client にはドメインを知らない素の口だけを置く。

### opt-in (ユーザー裁定 2026-09-21)

**キーが無ければ機構ごと存在しない。** 2 種類の API 契約を受領者に強いない。
`use_tts` 撤去後 (プレイヤー設定 1 本・既定 OFF) / 画像生成 `enabled` 既定 OFF /
`facts_policy` 既定 `locked` と同型。

### Phase 分け — 失敗コストの低い順に権限を上げる

Jev は**自分の判断を説明できない** (推論説明ができない) ので、却下権限は最後に渡す。

- **Phase A: 観測だけ。** 却下しない・還流しない・chronicle にもセーブにも入れない。
  dev mode のときだけ表示し、`app_data/logs/consistency.jsonl` へ追記。
  **engine・`run_turn`・prompt は一切触らない。**
  目的は**ベースライン (違反の発生率) の測定** — 今日の実ログ 11 ターンで実際の違反は 0 件で、
  分母が分からないと「還流で減った」が言えない。
- **Phase B: 還流。** ラベルのみを次ターンの prompt へ。A が「実際に起きる」と示したら。
- **Phase C: 却下。** 閾値を超えたら再生成。最後。

### Phase B の設計上の注意 (先に凍結)

**却下された語りをそのまま積んではいけない** — #47 の再演になる。

> ❌ 「前のターンであなたは『カウンター奥から源蔵が顔を出した』と書きましたが、源蔵は居ません」

これは**却下したはずの出来事を記録として確定させる**。積むのはラベルと統計だけで、
しかも #42 の処方 (何がダメかでなく何をすれば通るか) の向きにする。

> ✅ 「この卓では『この場にいない人物の発話』が 2 回検出されています。台詞を書く前に
> 現在の『この場にいる』一覧を確認してください」

**秘匿は還流に乗せない** (表示のみ)。ギャップ 0.41 で誤ラベルが積まれると、
**GM が萎縮して匂わせすらしなくなる** — ミステリの盤面では致命的。

効く見込みの根拠は spec 20 の読み側実測 (2026-07-21): ユーザーが「〇〇したら怒る」と宣言すると
GM は実際にその行動の後で怒り、**長く根に持った**。条件つきの未来規則が保持され条件成立時に
発火する経路は既に在る。

### Phase A で検査する軸 (ユーザー裁定で優先度を組み替え)

ユーザーが実害として挙げたのは「A の出身地が大阪、後に B が大阪」型の**設定の矛盾**であり、
移動・譲渡・不在発話ではない。ゆえに主軸を入れ替える。

1. **過去の語りとの矛盾** ← 主軸
2. **別人の特徴の混入** ← 主軸
3. profile との矛盾
4. 移動 (一方向) / 未所持物の譲渡 / 不在者の発話
5. 秘匿 (**表示のみ・還流対象外**)

### 照合の相手が存在しない層 (射程外)

| 層 | 照合の相手 | 状態 |
|---|---|---|
| (a) state との矛盾 | 所持品・presence・location | 実用レベル |
| (b) 作者が書いた設定との矛盾 | `attributes` / `profile` | 実用レベル |
| (c) ユーザーが宣言した設定との矛盾 | `facts` (既成事実) | 器は既にある |
| (d) GM の即興設定どうしの矛盾 | **無い** | 抽出機構が要る = 別 spec |

(d) は Jev だけでは解けない (Jev はテキストを生成できないので設定を抽出できない)。
ただし **Jev は state に 32k 使える** — GM の prompt が 11〜16k なら、**GM が見ているのと
同じ材料を Jev にも見せられる**ので、「GM が見ているのに矛盾した」は全部射程に入る。
50 ターンの全語りでも約 7,000 トークン = 0.04 円/ターン。
**捕まらないのは GM の材料から落ちた遠距離の設定だけ。**

(d) の本格的な処方は「あらすじ圧縮の瞬間に設定も抽出させる」形になるはず (spec 20 の教訓:
**LLM に副次的な記録作業をさせるなら主作業と同じ出力に混ぜない — 別の呼び出し・別の役割へ出す**)。

## Phase A の実装状態

### ✅ llm_client (2026-09-21)

`crates/llm_client/src/jev.rs` — v1 は **Noul のみ** (Choice/Score は Jev API に在るが
Phase A が使わないので実装しない = 収縮の Mandate)。

- `JevConfig::from_env()` — `JEV_ACCOUNT_ID` / `JEV_API_TOKEN` が**両方**揃ったときだけ `Some`
  (片方だけは設定漏れなので黙って既定へ落ちない)
- `encode` / `decode` は純関数。**`json()` 直でなく text→parse** (#34: 2xx で形が違うとき
  本文を捨てると「missing field」だけが残る)
- **402 (クレジット不足) はリトライしない** — `is_transient` が false。残高は再送で増えない
- PoC 7 本 + **live 2 本** (`tests/live_jev.rs`、`--ignored`)

live を付けた理由は spec 29 の教訓 (failures #99/#100): 「adapter の PoC は wire の形だけでは
相手の癖を捕まえない」。実際、**live が質問文の一文落ちを捕まえた** (0.87 → 0.51)。

## 接地の限界

  **live Jev との対比較ができていない** (private API 不可) ので、再現側の問題とも読める
