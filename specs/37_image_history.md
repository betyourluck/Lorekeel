# spec 37 — 挿絵の履歴 (生成した画像をシナリオごとに一覧する)

**Status**: Draft rev1 (2026-11-01 ユーザー要望 → 同日起草・実装)。契約は data_contract `ImageGeneration.history`。

---

## 動機

spec 24 の挿絵は**揮発**で、生成した絵は次の生成で差し替わり、手で「保存」を押さなければ残らない。
気に入った絵を後から見返す・比べる・捨てる、という鑑賞の往復が成立していなかった (ユーザー要望 2026-11-01)。

要望の形 (ユーザーの言葉をそのまま契約にした):

- 過去に生成したものを**シナリオごと**に履歴として一覧する。
- 会話ペインの挿絵の操作列に **□ が 4 つ (2×2) のアイコン**を足し、押すと過去に生成した画像の**サムネイル一覧**が出る。
- サムネイルをクリックすると**プレビューして大きく**なる。
- 一覧は**タイトルバーより下の全体**を使う 1 ページ。**戻る**でゲーム画面に戻る。
- **ログフォルダに `generated_images`** というフォルダを作り、そこへ画像を保存していく。ファイル名は `<パッケージの id>_<システム時間>`。
- 履歴一覧から**削除**もできる。

## 位置づけ

- 提示層だけ。正本・語り・prompt caching に触れない (spec 24 と同じ線)。
- 既存の「保存」ボタン (設定フォルダ `images/` へ `{日時}_{slug}_T{turn}` で書く) は**残す** — あちらは「持ち出す 1 枚」、
  こちらは「生成の記録」で、置き場も命名も目的が違う。
- セーブには入れない。履歴はディスクのフォルダそのものが正本で、一覧はフォルダを読んで組む (第二の真実源を作らない =
  spec 27 の参照ストックと同じ判断)。

## 決定

| # | 決定 | 根拠 |
|---|---|---|
| D1 | 置き場は **`<ログフォルダ>/generated_images/`**。ログフォルダは設定「ログ」の `kataribe.logDir` (空 = `app_data/logs`) | ユーザー指定。ログと同じフォルダ選択を使い、新しい設定欄を増やさない |
| D2 | ファイル名は **`{package_save_stem}_{unix_ms}.{ext}`**。stem = セーブ・参照ストックと同じ**パッケージパスの FNV-1a 16 桁 hex**、ms = 生成完了時刻の unix ミリ秒、ext は mime から (png / jpg / webp) | 「パッケージの id」をセーブと同じ鍵に揃える — 配布サイト由来でない手置きパッケージには id が無く、フォルダ名は別パスで衝突しうる。ミリ秒なら同一ターンの連打でも衝突せず、名前だけで新しい順に並ぶ (fs の mtime に頼らない) |
| D3 | **生成が成功するたびに自動で書く** (`generate_image` の中)。書き込みの失敗は生成を落とさず `GeneratedImageView.history_warning` に載せてトーストへ | 「そこに保存していく」= 手で押す経路ではない。失敗の沈黙は failures #98 の棚卸しの線で塞ぐ |
| D4 | 場面の世代 (`scene_seq`) が合わず表示を捨てる絵も**履歴には書く** | 課金は起きている (spec 30 の利用量と同じ理由)。捨てた絵を履歴から拾えるのは利点 |
| D5 | 一覧は**現在のセッションのパッケージの stem で前方一致**したファイルだけ。stem はセッションから取る (command は `folder` だけ受ける) | 「シナリオごと」の実体。他パッケージの絵を見せない・消させない |
| D6 | 削除は**ファイル名を受け取り、stem 前方一致・パス要素なし・拡張子が画像**を全部満たすものだけ消す | 別パッケージの絵や無関係なファイルを消す経路を作らない (`save_log_file` のトラバーサル遮断と同型) |
| D7 | サムネイルとプレビューは **`asset://`** (`list_generated_images` が `generated_images` フォルダを asset scope に許可)。data URL で全部読まない | 一覧は数十枚になる。参照ストックと同じ運び方 |
| D8 | 一覧ページは **タイトルバーの下の本体全体を差し替える** (右ペインも隠れる)。戻るボタンと Esc で閉じる。開いている間もターンは止めない (store の状態はそのまま)。**ヘッダのコンボリストで別のパッケージが選ばれたら畳んでゲームの画面へ戻る** (ヘッダは一覧の上に残る。一覧は選択中の盤面の絵なので、選択が替わった時点で前提が消える。監視はページ自身が持ち、開いている間だけ生きる) | ユーザー指定 (「タイトルバー以下全体のページ」/「コンボリストを切り替えたら一覧は終了して戻る」2026-11-01) |
| D9 | 削除は確認ダイアログを挟む | 不可逆で、押した直後の画面上の異変が小さい (1 枚消えるだけ) = シードリセット・「入れ直す」と同じ線 |
| D10 | 履歴から「挿絵として表示し直す」は v1 に**入れない** | 要望に無い。要れば `last_image` を差し替える command を足すだけ (第三層は data URL なので読んで渡す形になる) |

## 塞がない穴 (明記)

- ログフォルダを設定で変えると、以前のフォルダの履歴は一覧から消える (ディスクには残る)。ログの txt と同じ性質。
- パッケージを別のパスへ移すと stem が変わり、過去の履歴は結びつかなくなる (セーブ・参照ストックと同じ)。
- ファイル名の時刻は**生成完了時**の時計。時計を戻せば順序も戻る。

## PoC

- backend `image_history.rs`: ファイル名の形と拡張子 / 解析 (他 stem・パス要素・拡張子違いは拾わない) /
  フォルダの往復 (書く → 一覧が新しい順・他 stem は出ない → 削除 → 無関係な名前・他 stem の削除は拒否してファイルが残る)。
- frontend mount: 一覧が command の返りを描く / クリックでプレビュー・Esc で閉じる / 削除は確認の後に command を呼び一覧が更新される /
  戻るで store の `imageHistory.open` が折れる / 操作列のアイコンが一覧を開く / ヘッダのコンボリストの切り替えで畳む。

## 追補 (2026-11-01、ユーザー要望「リストの画像を参照画像に加える」)

参照ストック (spec 27) の空きの末尾の枠にある「いまの挿絵を入れる」の下に **「生成済みフォルダから」** のリンク。
押すと OS のファイル選択ダイアログ (`rfd`、`pick_package_folder` と同じ custom command = `pick_generated_image`) が
**`<ログフォルダ>/generated_images/` を初期位置に**開く (無ければ作ってから開く — 無いフォルダは初期位置に使えず
OS の既定位置へ落ちる)。選ばれたパスは `put_reference_from_path` が読んで枠へ入れる。

- **IPC にはパスしか乗らない** (`put_reference_from_asset` と同じ流儀)。読むのは backend の `ref_stock::read_image_file`
  で、**中身を読む前に大きさ (8MB) を見て、先頭バイトで mime を嗅ぎ分け、拡張子の申告を信じない**
  (`put_reference_bytes` と同じ規律。ダイアログの中で別のフォルダへ移って別の画像を選んでもよい)。
- WebP への変換は**しない** — 生成済みの絵は「いまの挿絵を入れる」と同じ原本を書く側 (ローカルファイルの取り込みだけが
  WebView で縮小する)。
- 一覧ページ (ImageHistoryPage) 側に「参照へ入れる」ボタンは置いていない — 参照は参照ストックの枠が入口、という
  spec 27 の形を崩さない (要望も参照ストック側のリンクだった)。
- PoC: app `ref_stock` +1 (拡張子 `.txt` の WebP を通し・中身が文字の `.png` を弾き・無いファイルとフォルダを拒む) +
  frontend mount +2 (空きの末尾にだけリンク・選んだパスで put・キャンセルは put を呼ばない)。Red はリンクを外す形と
  null を見ずに put を呼ぶ形で確認。**OS のダイアログそのものは mount でも dev サーバでも開けない** (Tauri 実機のみ)。
